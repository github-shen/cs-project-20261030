# 高优先级代码修复记录（2026-11-02）

本次修改基于原项目源码，保持现有 UDP 帧格式和转发配置格式不变。

## 已修复

### 1. 外部主机学习表的多线程数据竞争

- `Port` 增加 `learn_lock`。
- `learn_add()` 对学习表查找、更新、插入和轮转替换加锁。
- `learn_find()` 在锁内复制 `sockaddr_in`，不再把共享数组内部指针返回给调用者。
- `print_tables()` 读取学习表数量和内容时加锁。
- 每个端口创建时初始化互斥锁。

### 2. 配置文件参数严格校验

- 新增 `parse_uint()`，拒绝空值、非法字符、尾随字符、溢出和越界值。
- 校验节点 ID、端口 ID、本地/对端 UDP 端口、外部网络号、转发表键和转发表端口号。
- `port` 类型仅允许 `int` 或 `ext`；信道类型仅允许 `eth`、`wifi`、`bt` 或 `int`。
- 非法对端 IP、未知端口属性、属性缺少值均作为配置错误处理。
- 等价路径数量超过 `MAX_LB` 时明确报错，不再静默截断。
- 空转发表端口列表不再伪装成端口 0。
- 检查 `id` 必须存在且只能出现一次。

### 3. 统计计数器清零的原子性

- `reset_stats()` 对所有统计变量统一使用 `__atomic_store_n()`。
- 与接收线程中的原子递增操作保持一致。

## 编译与验证

使用以下命令编译：

```bash
make clean
make CFLAGS="-Wall -Wextra -Wpedantic -O2"
```

结果：`bin/switch` 和 `bin/host` 均编译通过，无编译警告。

已逐个启动并正常退出以下可直接在当前环境运行的配置：

- `config/node1.conf` 至 `config/node4.conf`
- `config-app/node1.conf`
- `config-lan/` 下配置（如存在）

负向测试：将配置中的本地 UDP 端口改为 `70000`，程序正确拒绝启动，并报告端口范围错误。

以下配置需要真实部署环境，不能在当前容器中作为失败判断：

- `config-nic-template/` 使用 `@A_WIFI@` 等待替换占位符，并依赖真实网卡名。
- `config-ovs/` 需要预先创建并配置 `10.1.0.x` 的 OVS 网络接口。

## 尚未实现、不能宣称已解决

UDP `sendto()` 成功只代表数据报交给本机协议栈，不代表远端收到。因此现有等价路径重试不能检测所有远端断链。真正的链路健康检测需要增加心跳控制报文、超时状态机、恢复策略和相应测试；本次没有擅自改变现有帧协议，建议单独立项实现。
